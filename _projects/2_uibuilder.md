### Project

Unity’s [UI Builder](https://docs.unity3d.com/6000.2/Documentation/Manual/UIE-data-binding.html) lacked data binding — a critical feature for real-world UI workflows. Without it, teams had to constantly switch between the Unity Editor and external code editors. This made collaboration between UI artists and UI developers frustrating and error-prone.

This project introduced data binding to the [UI Builder](https://docs.unity3d.com/6000.2/Documentation/Manual/UIE-data-binding.html), allowing teams to connect, preview, and test data-driven UI directly inside the Editor. The goal was to bring more of the UI development workflow into the Editor itself, reducing handoffs and workarounds.

### Role

I joined the early concepting phase of this project for 3 months. I collaborated with another senior designer, PMs, and the UI development team to map user journeys, define requirements, and design foundational UX flows.

- Led journey mapping for the UI artist persona, including scenarios, journey maps, and flow design  
- Partnered with developers to understand technical constraints  
- Co-authored user outcomes and UI requirements with senior designer and PM
- Designed low-fidelity workflows focused on binding creation and management

### Work

#### Mapping real workflows  
We began by mapping out the journeys of UI developers and UI artists. I focused on the artist perspective — documenting goals, actions, pain points, and emotional context as they moved between the Editor and external tools. These maps were validated through user interviews, with a focus on sentiment around data binding.

#### Defining requirements  
Together with PMs, we translated journey insights into outcome-based statements:  
> *"As a user, I want to [action] so that I can [goal]."*  

We grouped corresponding UI requirements into three areas:  
1. Discoverability  
2. Binding creation and management *(my focus)*  
3. Testing and validation

#### Designing foundational workflows  
I explored low-fidelity designs for binding creation and management in the UI Builder. Key questions included how users connect to data sources, manage bindings, and preview data-driven UI states.

I iterated on design in close collaboration with the dev team, a critical phase as technical constraints around system performance and serialization shaped many of our design decisions. We also ran a lightweight terminology study, which helped us refine language we initially assumed was standard.

#### Feedback and iteration  
We shared our work with the broader Unity Editor org to gather early feedback, identify edge cases, and validate our assumptions — setting a strong foundation for the next phase of development.

### Outcome

While I handed off the project before the high-fidelity design phase, my work helped define the scope and direction of the feature. The journey maps, user requirements, and workflows I created gave the team a strong foundation to build on.

In particular, my contributions helped bridge communication between design and engineering. By understanding and surfacing technical constraints early, I helped ensure we stayed grounded and avoided dead-end explorations.

### Reflection

This project taught me how essential it is to build trust and communication with developers, especially when working on highly technical workflows. The sooner you understand the system's constraints, the more effective your design work becomes.
